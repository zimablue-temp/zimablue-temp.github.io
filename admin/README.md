# Как редактировать сайт ZimaBlue

Это краткая инструкция для тех, кто меняет тексты и картинки на сайте
[zimablue.org](https://zimablue.org/). Редактирование идёт через встроенную
админку (Decap CMS) — программировать ничего не нужно.

## Как открыть админку

1. Откройте [https://zimablue.org/admin/](https://zimablue.org/admin/).
2. Нажмите «Login with GitHub» и войдите под своим аккаунтом GitHub.
3. Для входа нужен доступ на запись к репозиторию
   `zimablue-temp/zimablue-temp.github.io`. Если кнопка входа выдаёт ошибку
   доступа — попросите администратора добавить вас в репозиторий.

После входа слева появляется список разделов. Каждый раздел — это отдельный
кусок главной страницы.

## Какой раздел что меняет

| Раздел в меню слева | Что меняется на странице |
|---|---|
| **Настройки сайта** | `<head>` и мета-теги (title, описание), шапка (логотип, пункты меню, кнопка «Заказать исследование»), первый экран (заголовок и летающие теги), футер (ссылки, Instagram, подпись внизу) |
| **О нас** | Секция «О нас» |
| **Услуги** | Секция «Услуги» (карточки услуг) |
| **Преимущества** | Секция «Преимущества» |
| **Цифры** | Блок с показателями (числа и подписи) |
| **Исследования** | Секция «Исследования» (карточки исследований) |
| **Рекомендательные письма** | Секция «Отзывы» — вкладки с цитатами и всплывающие сканы писем |
| **Нам доверяют** | Лента логотипов партнёров |
| **Контакты** | Секция «Контакты» (email и Instagram) |

## Простой HTML в текстовых полях

Некоторые текстовые поля понимают простую разметку:

- `<i>…</i>` — курсив;
- `<br />` — перенос строки;
- `&nbsp;` — неразрывный пробел (склеивает предлог со следующим словом, чтобы
  он не «повисал» в конце строки);
- `&mdash;` — длинное тире, `&laquo;` `&raquo;` — кавычки-ёлочки.

**Ориентируйтесь на то, что уже написано в поле.** Скопируйте тот же приём из
соседнего текста, а не придумывайте новую разметку.

**Не вставляйте** в текстовые поля `<script>`, `<div>`, `<iframe>`, ссылки
`<a>` и другие структурные теги — это сломает вёрстку. Только `<i>`, `<br />`
и HTML-мнемоники вроде `&nbsp;`.

## Что происходит при сохранении

Кнопка публикации: **«Опубликовать» → «Опубликовать сейчас»**.

Каждое сохранение — это коммит в ветку `main`. После публикации GitHub Actions
автоматически пересобирает сайт, и через примерно **1–2 минуты** изменения
видны на [zimablue.org](https://zimablue.org/). Обновите страницу, если не
видите правок сразу.

## Про «большой дифф» при первом сохранении раздела

Когда какой-либо раздел сохраняется через админку **в первый раз**, Decap
переписывает соответствующий файл `_data/*.yml` в своём стиле: длинные тексты,
которые раньше были свёрнуты (`>-`), становятся обычным многострочным текстом,
а кавычки вокруг простых строк убираются.

**Текст и внешний вид сайта при этом не меняются** — сдвигается только
форматирование самого файла. Это нормально, ожидаемо и безопасно. Тот, кто
будет просматривать такой коммит, не должен пугаться большого на вид диффа.

## Раздел «Рекомендательные письма»: поле `slug`

У каждого письма есть поле **`slug`**. Оно:

- должно быть **уникальным** среди всех писем;
- может содержать только строчные латинские буквы, цифры и дефис
  (`^[a-z0-9-]+$`), например `tele2`, `british-council`.

`slug` задаёт «якорь» всплывающего окна (модалки) с этим письмом.
**Переименование `slug` переименовывает этот якорь.** Меняйте его только если
понимаете зачем.

Загрузка картинок в этом разделе:

- **скан письма** (`letter_image`) кладётся в `src/docs/`;
- все остальные изображения (логотипы, картинки) — в `src/img/uploads/`.

Админка сама подставляет правильную папку в зависимости от поля — просто
загружайте файл через кнопку выбора изображения.

## Редактирование без входа в GitHub (для разработчиков)

Можно править контент локально, без логина и без интернета. Из корня
репозитория:

```bash
npm ci
```

Затем в двух отдельных терминалах:

```bash
npx @11ty/eleventy --serve      # терминал 1: сайт на http://localhost:8080/
npm run cms                     # терминал 2: локальный бэкенд Decap (decap-server)
```

Откройте [http://localhost:8080/admin/](http://localhost:8080/admin/). Decap
покажет надпись «local backend» и будет писать изменения прямо в файлы
`_data/*.yml` на диске — вход через GitHub не нужен. Дальше эти файлы можно
закоммитить обычным образом.
